# Virelia world foundation v0.1

The [v0.2 playable prologue](VIRELIA_PROLOGUE.md) builds on this foundation,
adds the player's home, replaces the normal new-game start with the story and
makes the original development gateway an explicit build configuration. This
document records the original map foundation; use the prologue document for
current progression and playtesting instructions.

## Scope and baseline

This milestone adds four explorable Virelia maps to the Emerald build based on
`pokeemerald-expansion` 1.17.1. `codex/virelia-world` starts at the committed
starter revision `960b3cf8cd0f283b9afd553d7e4df129aea73a02`, whose
[baseline CI run](https://github.com/hkcmoris/romhack/actions/runs/39425525301)
passed. The starter branch is not modified.

Virelia is the planned main-game region; Hoenn is planned as the complete
postgame region. This foundation supplies a small connected test area. It does
not yet switch the new-game starting location or add postgame progression.
Existing Hoenn maps and story scripts remain in place. The inherited Duo quick
start, regional starter scientist, and original Battle Tower Link Multi test
remain available.

All area names are provisional English names. No Gym battle, campaign story,
Rocket mission, Mega Evolution, second League, custom graphics, or upstream
experimental multi-region engine is introduced.

## Initial area

```text
                   Slateford City
                         |
                  north/south edge
                         |
            Route 01 — Whisperwood Trail
                 | optional item path
                         |
                  north/south edge
                         |
                  Maplebrook Town
                   |           |
            research lab   development guide
                               |
                         Littleroot Town
```

The overworld maps all have width 30. Reciprocal north/south connections use
offset `0`, with aligned openings at columns `14` and `15`. Walking north from
Maplebrook leads to Route 01; walking north from Route 01 leads to Slateford.
Both transitions can be crossed southward without a ledge, HM, badge or story
flag. Coordinates in this document use Porymap's zero-based map coordinates.

Maplebrook provides a rural starting-town exterior, the player's home
exterior, a laboratory exterior, signs and a clear road north. The home is an
exterior placeholder. The laboratory is the working building entrance for
this milestone. Its doorway at `(24, 18)` is town warp `0`, targeting laboratory
warp `0` at `(6, 12)`. Both laboratory exit tiles, warps `0` and `1` at
`(6, 12)` and `(7, 12)`, target town warp `0`. The home door at `(7, 9)` and
cottage door at `(22, 9)` are closed placeholders with explanatory dialogue.

The research laboratory contains a professor, research furniture, and three
starter display positions with placeholder dialogue. These displays do not
replace the existing regional starter test NPC or implement the campaign's
starter selection. Use the Littleroot scientist to obtain the already
implemented regional starters. The professor at `(6, 4)` heals the party without
changing its last healing destination. Item-ball display objects at `(4, 6)`,
`(6, 6)` and `(8, 6)` describe the Grass/Dark, Water/Bug and Fire/Poison
families respectively.

Whisperwood Trail contains trees, several short paths, tall grass with ordinary
wild encounters, and an optional item area. A walkable route connects both
towns. The wild encounter table in `src/data/wild_encounters.json` belongs only
to the new route. Its land encounter rate is `20`; this is the engine's encounter-rate
parameter, not a flat 20% chance per step. The twelve native slot weights are
20, 20, 10, 10, 10, 10, 5, 5, 4, 4, 1 and 1 percent.

assets are documented in [Virelia starters](VIRELIA_STARTERS.md).
No original graphics file is recolored or replaced.

Open this repository in the installed Porymap and find the new Virelia map
groups. Edit only the new maps and layouts for this milestone. Preserve the
passable edge openings, reciprocal connection offsets, paired laboratory
warps, event positions and collision/elevation settings when changing tiles.
An attractive tile that has the wrong behavior can block an entrance or remove
grass encounters. `tools/virelia/generate_layouts.py` reproduces the initial
binary layouts; running it replaces the generated map files and therefore
also replaces later Porymap tile edits. Prefer Porymap for subsequent mapping,
or update the generator deliberately before regenerating.

## Development access

`VIRELIA_WORLD_TEST` in `include/config/general.h` is a numeric `1`/`0`
development switch. When enabled in Emerald, the existing Duo guide in
Littleroot at `(17, 12)` gains **VISIT VIRELIA**. The existing **TRAVEL TO TOWER**
and **TEST TEAM SETUP** actions retain their original behavior. The regional
starter scientist at `(18, 12)` remains separate.

The visit option requires at least one conscious, non-egg Pokemon and refuses
travel during an active Frontier challenge. It takes the player to Maplebrook
at `(14, 21)`. The return scientist at `(16, 21)` takes the player back to
Littleroot at `(17, 13)`, subject to the Frontier challenge guard. Return access
remains available if the development entry option is disabled later, so a save
inside Virelia is not stranded by that switch.

Travel does not replace or grant Pokemon, reset a Frontier challenge, or change
the new-game starting location. The world switch is independent of the existing
quick-start and starter-test switches. FireRed and LeafGreen do not expose this
development travel.

There is no Virelia Pokemon Center or new heal location yet. The native
blackout flow uses the save's existing Hoenn healing destination. The laboratory
professor heals the party locally without registering a new respawn point.
Include blackout behavior in testing.

## Build and test

Use the existing [GitHub Actions CI workflow](https://github.com/hkcmoris/romhack/actions/workflows/build.yml)
on **`codex/virelia-world`**. Select the run for the exact intended commit and
wait for Emerald development, Emerald release, FireRed, LeafGreen, native
tests, documentation validation and the aggregate `build` check to succeed.
Download `emerald-release` and extract `oraculum-v0.1.N-release.gba`, where
`N` is the workflow run number. GitHub Actions compiles the ROM; no local
Ubuntu or WSL installation is needed.

Use a backed-up compatible save or a separate new test save. For a new game,
finish the inherited Duo quick-start team prompt. For an existing save, retain
the current party or use the existing test tools as described in
[Duo multiplayer testing](DUO_MULTIPLAYER_TEST.md) and
[Virelia starter testing](VIRELIA_STARTERS.md).

### Playtest procedure

1. Record the commit, Actions run, artifact and ROM SHA-256. Load the Emerald
   ROM and confirm the inherited quick start still reaches Littleroot.
2. Speak to the Duo guide. Cancel **VISIT VIRELIA** once, confirming that no
   travel or party changes occur. Accept it next and confirm arrival on
   walkable ground in Maplebrook. Check that the regional starter scientist
   remains accessible separately.
3. Walk around Maplebrook, read the signs and inspect the home and laboratory
   exteriors. Enter the laboratory, speak to the professor and inspect all
   three starter displays. Verify that the professor restores HP, PP and
   status. Exit and enter again to check both warp directions
   and doorway animation.
4. Walk north into Whisperwood Trail. Explore each short path, walk through
   grass until a wild battle starts, and confirm the encounter is from the
   route's table. Use a regional starter in battle and inspect its types,
   moves, sprite and party summary. Test ordinary capture or flee behavior.
5. Visit the optional item area and collect the item. Leave the route, re-enter,
   and confirm the collected item stays gone. Include the normal Bag-full
   refusal behavior when testing item handling.
6. Continue north into Slateford. Inspect the mining scenery, building
   placeholders and Gym exterior. Walk back south through the route to
   Maplebrook; verify both map seams in both directions.
7. Make a normal in-game save in **each of the four maps**, reset the emulator
   and choose **CONTINUE**. Confirm the same map, coordinates, party and
   collected-item state reload; move and interact afterward. An emulator save
   state does not substitute for this check.
8. Return to Littleroot through the Maplebrook scientist. Verify the original
   Hoenn map, entrances and nearby routes remain usable. Repeat travel to
   Virelia and back without receiving duplicate Pokemon.
9. Repeat the regional starter grant, evolution, PC and save checks in
   [Virelia starters](VIRELIA_STARTERS.md). Repeat the existing Duo **TRAVEL TO
   TOWER** and return flow, then the two-player Link Multi procedure with two
   identical ROMs. Native battle and link tests are not a substitute for the
   two-device test.
10. Check that entry without a conscious non-egg Pokemon is refused and that
    active Frontier challenges block shortcut travel. Test blackout from a
    backed-up Virelia save and confirm recovery at the existing heal location.
    Do not bypass or erase native Frontier challenge state to test the guard.
11. Build with `VIRELIA_WORLD_TEST` set to `0`: confirm the entry option is
    absent, then load a backed-up save in Virelia and confirm the return guide
    still works. The four maps remain part of the Emerald ROM.

## Multi-region limits and save behavior

- Every new `map.json` deliberately declares `"region": "REGION_HOENN"`.
  `tools/mapjson/mapjson.cpp` filters Emerald map data to that value and
  FireRed/LeafGreen map data to `REGION_KANTO`. A new `REGION_VIRELIA` string
  alone would exclude these maps from the Emerald build. The separate map
  groups and constants identify Virelia without changing this filter.
- `include/constants/regions.h`, `include/regions.h` and `src/region_map.c`
  still use the engine's existing region model. The appended Virelia sections
  are classified as Hoenn by `GetRegionForSectionId`. Section names identify
  the new locations, but this does not provide a separate Virelia Town Map,
  PokeNav map, Fly destinations, regional Pokedex or region-selection UI.
- The optional Gen 5 map-name popup table is sized to the full section range,
  matching the default popup table. Appended Virelia sections use the default
  theme safely in either style.
- Section footprints provide nonzero dimensions required by the current map
  cursor calculations. They are compatibility metadata, not a drawn Virelia
  world map. No existing Hoenn map-art cell or Fly destination is repurposed.
- Map group/map numbers, layouts, coordinates, encounters and event flags use
  the existing engine data structures. This milestone adds no save field and
  changes no save format. Map-section IDs remain within the stored byte range;
  future growth must also respect the reserved met-location values at
  `0xFD`–`0xFF`.
- Save compatibility depends on matching engine/configuration and retained
  IDs. A save made in Virelia references maps absent from the old starter-only
  ROM. Do not load that save in the older ROM. Keep an external backup before
  switching builds. Future edits must append IDs and preserve existing IDs
  unless an explicit migration is designed.
- Hoenn remains the original complete region data, with its original story
  scripts. Making it reachable as a paced postgame requires a later campaign
  design. The inherited test quick start is not a full Hoenn story unlock.

## Planned expansion

After the first-area playtest is accepted, expand Virelia in small connected
milestones: complete Maplebrook interiors, add Slateford services and mine
access, then extend routes and settlements. Define the full-region geography,
travel links, healing points and story progression before adding the first
Gym battle or changing the production starting map.

Separate-region map graphics and selection, Fly/heal destinations, encounter
area display, met-location handling, regional Pokedex rules and the transition
to postgame Hoenn need a reviewed technical design. Review any upstream
multi-region proposal before merging it. Keep Hoenn's existing identifiers and
content stable and evaluate save compatibility for each later change.

Final tilesets, sprites, names, starter selection, story events, Gyms, Rocket
missions, Mega Evolutions and an additional League remain future work. This
branch stops at the four-map foundation.
